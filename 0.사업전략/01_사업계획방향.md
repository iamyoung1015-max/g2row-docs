## 1. 사업 정체성

### 1.1 한 줄 정의 `확정`

> **제조·물류에 특화된 AX(AI 전환) 구축 파트너**

### 1.2 범위를 좁힌 이유

- 이전 메시지는 "AX 파트너"로 범위가 넓어 **정체성이 흐렸음**
- "교육 사이트인가, 구축 사이트인가"가 외부에서 구분되지 않았음
- 따라서 **① 업역(제조·물류) ② 기업 규모(소규모) ③ 역할(구축 파트너)** 세 축으로 압축

### 1.3 포지셔닝 3축

| 축 | 정의 | 근거 |
|---|---|---|
| 업역 | 제조·물류 | 현재 수행 중인 영역, 레퍼런스 보유 |
| 규모 | 소규모 기업 우선 | 대기업은 프로그램 복잡도보다 **사용자 수·의사결정 주체 수**가 병목. 소규모는 빠르게 보여주고 → 빠르게 의사결정 → 바로 사용 |
| 역할 | 프로그램만 파는 회사가 아님 | 프로그램 + 운영 인력 + 조직 문화 + 경영진 의지를 **통합적으로 다루는 파트너** |

### 1.4 기존 방향과의 관계

> 녹취: *"라면 끓이듯 누구에게나 만족할 수준은 아니다."* / *"대한민국을 다 장악할 필요는 없다."*

## 3. 핵심 메시지 전략

### 3.1 메시지 전환의 핵심 논점

- 기존 셀링 포인트 후보: "개발 환경 세팅이 어렵다 → 우리가 대신 해준다"
- **문제점**: 비개발자는 *개발 환경 세팅이 어렵다는 사실 자체를 모름* → 셀링 포인트로 작동하지 않음
- **결론**: 허들 제거가 아니라 **결과물**을 먼저 보여주는 메시지로 전환

### 3.2 채택 메시지 `확정`

> **"엑셀 쓸 줄 아시나요? 엑셀 쓰시면 프로그램 만들 수 있습니다."**
> **"본인이 쓰던 재고관리 엑셀을, 단 4시간 만에 개발·배포해서 바로 씁니다."**

### 3.3 메시지 전개 순서 (랜딩/영상 공통)

1. **후킹** — 엑셀 → 프로그램 (결과 제시)
2. **시연** — 엑셀 시트 화면 → 프로그램 화면으로 전환되는 영상
3. **허들 설명** — "원래는 클로드·파이썬 설치 + 서버 세팅 + 배포라는 허들이 있다"
4. **해소** — "키트 플랫폼 접속 → 입력 → 클릭 → 4시간 만에 결과"
5. **확장** — "반복할수록 정교해진다. 물고기를 주는 게 아니라 **잡는 법**을 알려준다"

**정의**: 개발 환경·서버·배포를 통째로 패키지화한 **올인원 실물 상품** (밀키트 컨셉)

**차별화 지점**

- **온프레미스 / 사내 유휴 PC 설치** 지원 → 제조·물류 기업의 **데이터 외부 반출 거부감**을 정면 해소
- 상품 상세 구성은 **5.2 키트** 참조

### 4.3 ② 마켓 활성화 `잠정`

> **미확정.** 2026-09-04 대표 지시로 **"자사 공급 템플릿 마켓" 방향으로 기록**하되, 확정된 안이 아님.
> 원본 녹취·키트구성안에는 해당 개념이 등장하지 않음.

**현재 기록된 방향**

- 제조·물류 **업종별 프로그램 템플릿**을 G2ROW 개발팀이 제작·공급하는 마켓
- 키트 구매자·교육 수강생이 템플릿을 **골라서 즉시 적용** → 초안 품질 상향

```
G2ROW 개발팀
  └ 업종별 템플릿 제작
       ├ 재고관리 (제조)
       ├ 입출고/배차 (물류)
       ├ 생산일보
       └ 견적
            └ 키트 사용자가 선택 → 즉시 적용 → 커스터마이징
```

**근거 (녹취와의 연결)**

> *"자동 플랫폼 관련 부분들이 우리 개발팀에서 **템플릿을 업데이트하다 보니** 조금 더 **일반화**된 거지."*

→ 이미 내부에 템플릿 축적이 진행 중이므로 마켓의 실질 재료가 존재

**기대 효과**

- **초안 품질 상향** → 교육 4시간 내 결과물의 완성도 확보
- **교육 실습 재료** 확보 (커리큘럼 3단계에 바로 투입)
- 템플릿이 쌓일수록 **후발 진입장벽**으로 작동

**보류된 대안** (기록만)

- 사용자 제작물 유통 마켓(네트워크 효과형) → 초기 콘텐츠 공백 문제로 2단계 검토 대상
- 스마트스토어 등 외부 판매채널 활성화 → 이는 마켓이 아니라 **유통 채널** 이슈로 7.2에서 다룸

### 4.4 ③ 위탁개발 구독제 `잠정`

> **미확정.** 2026-09-04 대표 지시로 **아래 두 방향을 모두 기록**. 택일 또는 결합 여부 미정.
> 원본 녹취·키트구성안에는 해당 개념이 등장하지 않음.

#### 방향 A — 월정액 개발 대행

건별 견적을 없애고 **월 정액으로 개발 요청을 처리**

```
기존: 문의 → 상담 → 견적서 → 계약 → 개발
      (대표 로딩 과다 / 정찰가 불가 / 랜딩에 가격 노출 불가)

구독: 월 정액
      ├ 매월 개발 요청 N건 처리
      └ 건별 견적 협상 없음
```

**해결하는 문제 (녹취 근거)**

> *"견적서가 별거 아닌데, 견적서 주는 데까지 나한테 로딩이 너무 많이 걸리는 거라."*
> *"우리가 비용이 정찰가가 아니잖아요."*

→ **내부 병목(견적 로딩)** 과 **외부 문제(가격 비공개)** 를 동시에 해결
→ 랜딩에 **가격 공개가 가능해짐** (7.3 가격 정책의 핵심 해법)

#### 방향 B — 구축 후 유지보수 구독

개발은 별도 계약, 이후 **운영·개선·장애 대응만 월 구독**

```
1) 구축 계약 (별도 견적)
     ↓
2) 월 구독 전환
     ├ 장애 대응
     ├ 기능 개선 요청
     └ 버전 업데이트
```

**흡수 대상**: 교육 이수 후 **A형 고객**(초안은 만들었으나 직접 유지보수는 못 하는 층) — 5.3 참조

#### 두 방향의 관계

- A와 B는 배타적이지 않음. **A를 상위 플랜, B를 하위 플랜**으로 2단 구성하는 안도 가능
- 결정 필요 사항은 **7.4**에 집계

### 4.5 세 축의 연결 구조

```
① 개발키트로 진입 (환경 장벽 제거)
        ↓
② 마켓 템플릿으로 초안 품질 확보
        ↓
   교육 이수 → 고객 분기
        ├ B형(심화) → 직접 유지보수 → 키트 재구매·업그레이드
        └ A형(단순) → ③ 위탁개발 구독제로 흡수
                          ↓
                    구독 매출 = 예측 가능한 현금흐름
                          ↓
                    그 여력으로 ② 템플릿 재투자
```

**핵심**: 세 축이 각각의 상품이 아니라 **하나의 순환 구조**. 교육에서 이탈하는 고객이 곧 구독제 고객이 되므로, **교육 실패가 매출 손실로 직결되지 않는다.**

## 5. 상품 구성

### 5.1 전체 구조

```
AX 구축 파트너
├── ① 키트 (Kit)       : 올인원 개발·배포 환경 (하드웨어 + 소프트웨어 + 플랫폼)
├── ② 교육             : 비개발자 실무자 대상 2~4시간 단기 과정
├── ③ 구축             : 기업 맞춤 시스템 구축 (기존 사업)
└── ④ 유지보수·후속관리 : 교육 이수 후 분기 지원 → 구독제로 전환 검토(4.4)
```

### 5.2 키트 (Kit)

**컨셉: 밀키트** — 환경 세팅부터 배포까지 전 과정을 패키지화한 올인원 상품.

#### (1) 사전 세팅된 개발 환경 (소프트웨어)

- Python, Claude API, VS Code, 웹 서버, 데이터베이스 **전부 설치·설정 완료 상태로 제공**
- 사용자는 **원격 접속만 하면 즉시 개발 시작**

#### (2) 하드웨어 옵션

| 구분 | 사양 | 용도 |
|---|---|---|
| 미니 PC | 저사양 | 공간 절약, 간단한 업무용 프로그램 |
| 일반 PC | 표준 | 통상적인 제조·물류 실무 프로그램 |
| 워크스테이션 PC | 고사양 | 대용량 데이터 처리, 고성능 연산 |
| **유휴 PC 활용** | 하드웨어 미구매 | 사내 남는 PC·개인 PC에 동일 환경 직접 설치 |

- 플랫폼은 **4개 옵션 모두 동일**. 차이는 **서버(하드웨어) 구매 비용**뿐
- 옵션 상품으로 **백업 서비스** 등 추가 구성 가능

#### (3) 자동 초안 생성 및 배포 플랫폼 (인프라)

1. 플랫폼 로그인
2. 프로젝트 생성 → 요구사항 입력
3. **프로그램 초안 자동 생성**
4. 버튼 클릭 → **자동 배포**, 서버 인프라·배포 상태 자동 관리

#### (4) 유지보수 및 코드 편집

- 생성된 코드 폴더가 보관됨 → **VS Code 또는 Claude Code**로 접근
- AI에게 수정 요청("여기에 이 기능 추가해줘") 또는 직접 코드 편집으로 **점진적 고도화**

### 5.3 교육 프로그램

- **대상**: 제조·물류 수요 기업의 비개발자 실무자 (엑셀 기반 업무자)
- **시간**: 2~4시간 단기 과정
- **철학**: 완제품 전달이 아니라 **"물고기 잡는 법"** 전수

#### 커리큘럼 흐름

| 단계 | 내용 |
|---|---|
| 1. AX의 통합적 이해 | AX = 소프트웨어 도입만이 아님. **실무 인력 + 조직 문화 + 경영진 의지**의 결합 |
| 2. 개발 환경 진입 | 인프라 설정 생략, 준비된 키트 플랫폼 접속 및 기능 습득 |
| 3. 초안 개발 실습 | 실무에서 쓰던 **재고관리 엑셀·요구사항 입력 → 수 시간 내 작동 화면 생성** |
| 4. 배포 및 반복 피드백 | 직접 배포 → AI 프롬프트로 기능 추가하며 점진적 완성 |
| 5. 사후 유지보수 | **분기 지원**: (A) 초안 그대로 실무 활용 (B) VS Code 등으로 독립 유지보수 |

#### 교육 이수 후 고객 분기 (중요)

- **A형 (단순 활용)**: "이렇게 되는구나" 확인 후 초안 결과물을 그대로 실무 적용
  → **위탁개발 구독제(4.4)의 주 타깃**
- **B형 (심화)**: 새로운 걸 깊게 파는 성향. 직접 유지보수·확장까지 진행
  → **키트 업그레이드·마켓 템플릿의 주 소비층**

### 5.4 기대 효과

- **실무자**: 단시간 내 직접 결과물을 만들고 배포하는 **성취감**
- **기업**: 외주 개발 의존 없이 **자체 AX 역량 내재화**

## 6. 채널 및 영업 전략

### 6.1 기본 관점 — 인바운드 중심

> 녹취: *"고객이 우리를 어떻게 알고 문의가 오지? **인바운드** 개념에서 블로그를 하는 거지. 아웃바운드까지 하면 좋지만, 앞으로도 형태가 그럴 거야."*

- **인바운드 우선**: 블로그 · 스레드 · 랜딩 페이지
- AI로 만드는 과정을 **리빌딩한 뒤 새로 콘텐츠화 → 바이럴**

### 6.2 온라인 (랜딩 페이지 / 홈페이지)

- **원칙**: 심플할수록 좋음. 한 번에 다 담지 않고 **순차적으로 확장**
- 9월 기준 목표: **완성도가 아니라 "틀"을 먼저 만든다**

### 6.3 공공·지자체 채널 (울산 사례)

- 배경: 울산시도 타 지자체와 마찬가지로 AX·AI에 관심 높음
- **역제안 전략**: 공무원 조직에서는 기획이 자체 발의되기 어려움 → **제안서 포맷을 먼저 만들어 전달** → 내부 검토 후 역으로 연락 오는 구조
- **접촉 경로**: 경제진흥원, 상공회의소 등
- **실행안**: 오프라인 **무료 세미나** 주최 (기관이 인원 모집) → 교육 진행 → 말미에 프로그램 소개
- **필요 자료**: 과거 스마트팩토리·정부지원사업 사례, 기존 구축 레퍼런스(홈페이지·블로그 히스토리), 데모 영상
- **정치 지형 참고**: 울산시장과 시의회·국회의원 정당이 달라 하향식 추진이 원활하지 않음 → **상향식(실무 제안) 접근이 유효**

### 6.4 파일럿 / 수요 검증

- 지인 및 문의자 대상 **무료 교육·웨비나** 진행
- **설문지 배포**로 실제 신청 수요 측정 (스레드 등 SNS 채널, 보유 중인 **이벤트 사이트** 활용)
- → 반응을 보고 **정식 상품화 여부·형태 결정**
- 기대: *"하나 두 개 세 개 네 개 쌓여서 단단해지고, 고객이 생기고 레퍼런스가 생기지 않을까"*

### 6.5 콘텐츠 자산

| 자산 | 현황 | 활용안 |
|---|---|---|
| 데모 영상 | **약 20분 보유** (제조업 도입부 + '밀키트' 컨셉 프로그램 시연) | 편집·압축하여 랜딩·세미나에 사용 |
| 기존 구축 히스토리 | 자사 홈페이지·블로그에 축적 | 레퍼런스로 재활용 |
| **유튜브 '한부장'** `미정` | 구상 단계 | 격주 1회, 현장 사연 접수 → 상담·해결 과정 공개. **조회수 목표 없음**, 현장 이해 축적 + 인바운드 유입 목적 |

### 6.6 내부 병목 — 견적 프로세스 `미정`

> 녹취: *"견적서가 별거 아닌데, 견적서 주는 데까지 나한테 로딩이 너무 많이 걸린다."*

**구상안**: 전화 상담 → **전사록이 그대로 클라우드 플랫폼에 유입** → **제안서·견적서·프로그램 초안까지 자동 생성**

- 고객 유형별 대응: 문서를 빨리 주는 고객 / 말로만 설명하는 고객 → **후자를 전사록으로 흡수**
- **위탁개발 구독제(4.4-A)의 원가 구조를 성립시키는 전제 기술** — 견적 로딩이 사라져야 정액제 단가가 나옴

## 9. 핵심 원칙 요약

1. **줄인다** — AX 전체가 아니라 **제조·물류**, 대기업이 아니라 **소규모**.
2. **결과를 먼저 보여준다** — 허들 설명이 아니라 "엑셀 → 4시간 → 프로그램".
3. **물고기 잡는 법을 가르친다** — 완제품 납품이 아니라 역량 내재화.
4. **통합적으로 접근한다** — 프로그램 + 인력 + 조직 문화 + 경영진 의지.
5. **세 축은 하나의 순환이다** — 키트로 들어와서, 마켓으로 품질을 얻고, 못 하면 구독으로 흡수한다.
6. **한 번에 다 하지 않는다** — 랜딩은 심플하게, 순차적으로 채운다.
7. **콘텐츠가 없으면 홈페이지도 없다** — 7장 미결정 과제 해소가 최우선.
